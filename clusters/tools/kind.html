Deploy a Kind cluster

kind cluster creates a container-based cluster. So, our actual nodes are containers inside containers. Although, I believe that the kind is the best option to experience Kubernetes without spending too much time to deploy one or money on hardware. We can have several multi-node clusters just in the expense of your laptop or an old unused personal computer.

Default

kind uses our container runtime interface (CRI) to deploy multiple containers that would be represented as nodes. Then it deploys k8s on the created containers. However, this type of installation has its own pros and cons but I believe that it is the fastest way to have multiple clusters on-premise and experience with k8s as fastest as possible.

We can customize kind later on degrade some of those limitations, although accessing a cluster on your laptop or home lab the fastest enough that could help you understand the entire ecosystem of k8s is something we should not think twice.

The latest document of kind is always aligned with the latest changes to it. Although, we can follow the below installation guideline to have our first cluster in our local machine, I believe referring to Kind Quick Start website for the ultimate installation process or further troubleshooting scenarios.

Installing kind
case "$(uname -m)" in aarch64) arch="arm64" ;; x86_64) arch="amd64" ;; *) echo "Unsupported architecture" >&2; exit 1 ;; esac
OS=aarch64 && [ $(uname -m) = aarch64 ] && sudo curl -Lo /usr/local/bin/kind https://kind.sigs.k8s.io/dl/v0.33.0/kind-linux-arm64
sudo chmod +x /usr/local/bin/kind
kind version
Creating our cluster with default configuration
kind create cluster --name NAME

I always like to work neat so I specify a name for my cluster, for example, stage.

Listing our nodes (they are just containers 😂)
kind get nodes
Removing a cluster is as simple as running the following command
kind delete cluster --name NAME

Customization

One of the limitation of kind is port-forwarding. When we want allow external traffic to our cluster we experience limitations since kind opens ports just on control-plane nodes. If we, therefore, need to allow traffic into our cluster we require to add the following customization to our cluster.

Installing kind with custom configuration
sudo curl --config

For further information on the customization our go to solution is the kind’s configuration page.
